How AI agents work

An agent is a language model in a loop that can use tools. That one sentence explains Claude Code, Codex and OpenClaw. This guide builds one from nothing, piece by piece, with a video, an animated presentation and code you can run on your own laptop.

01The whole idea in four parts

Everything else in this guide is a refinement of these four.

brain

A model that predicts text

Given some text, it predicts the next token. No memory, no clock, no hands.

memory

A list called the context

Every message is kept in a list, and the whole list is sent on every call.

hands

Tools

The model asks for a function to be called. Your program runs it and adds the result.

engine

A loop

Keep calling the model while it asks for tools. Stop when it answers.

02Concepts, one at a time

Each concept has a runnable step in practice/. The snippets below are shortened versions of those files.

The model predicts the next token

A large language model does one thing: given some text, it predicts the next token, a word or part of a word, and then does it again. It has no memory between calls, it does not know what time it is, and it cannot touch anything.

Everything it knows about your situation has to be in the text you send. That text is the context.

A chat is a list

The chatbot does not remember the conversation. The program does: it keeps a list of messages (a system message with instructions, your messages, the model's replies) and sends the whole list every time.

This is the pattern from Thomas Ptacek's “You Should Write An Agent”, and it is the only memory a model has. 01_chat.py

context = [{"role": "system", "content": "..."}]

while True:
    line = input("You: ")
    context.append({"role": "user", "content": line})
    reply = call(context)          # the whole list
    context.append({"role": "assistant", "content": reply})
    print(reply)

Tools: the model asks, the program acts

Along with the messages, you send descriptions of tools: a name, what it does, and its arguments as JSON Schema. The model cannot run anything, but it can reply with a tool call: “please call clock”.

Your program runs the real function, adds the result to the list as a new message, and calls the model again. Now the answer is in its context. 02_one_tool.py

{"type": "function", "function": {
   "name": "clock",
   "description": "Returns the current local date and time.",
   "parameters": {"type": "object", "properties": {}}}}

# the model replies:  tool_call: clock()
# the program runs:   clock() -> "Thursday 15 October 2026, 12:12"
# the model answers:  "Tomorrow is Friday."

The loop is the agent

Put the tool step in a loop. Call the model; if it asks for tools, run them, add the results and call it again; if it answers without a tool call, it is done.

The model decides how many steps it needs. Your code only sets the maximum. Every agent product is a variation of these eight lines. 03_agent_loop.py

for step in range(MAX_STEPS):
    reply = call(context, tools)
    context.append(reply)
    if not reply.tool_calls:
        return reply.content          # done
    for request in reply.tool_calls:
        result = run(request)
        context.append(result)

One tool to rule them all: the shell

Tools can be anything code can do. One is special: a bash tool lets the agent run any command on the computer. Models have read millions of shell commands, so one tool unlocks thousands of abilities. That is how coding agents work, and why they need guardrails.

In the practice code, every shell command needs your approval first.

def run(name, a):
    if name == "bash":
        if input(f"allow? $ {a['command']} [y/N] ") != "y":
            return "The user refused to run this command."
        p = subprocess.run(a["command"], shell=True,
                           capture_output=True, text=True, timeout=60)
        return (p.stdout + p.stderr)[-20_000:]

Context engineering and compaction

Everything lives in the context: system prompt, tool descriptions, skills, memory, the conversation and every tool result, and the whole thing is re-sent on every step. It fills up fast, costs more as it grows, and past a point the model gets worse at using it.

When it is nearly full, agents compact: the model summarises the older part, and the summary replaces it, while the latest messages are kept word for word. Something is always lost. Choosing what to keep is context engineering. 04_context.py

def compact(context):
    system, old, recent = context[0], context[1:-4], context[-4:]
    summary = call([{"role": "user", "content":
        "Summarise this conversation in under 120 words. "
        "Keep names, numbers, decisions and open questions."
        + transcript(old)}]).content
    return [system, {"role": "user", "content": summary}] + recent

Memory across sessions

The context disappears when the program stops. The simplest memory is a file: give the agent a remember tool and read the file back into the system prompt next time.

Real systems add search, keyword search (grep) or vector search with embeddings, so only relevant memories enter the context. Forgetting matters too: a memory full of trivia is noise. 05_memory.py

TOOLS = [tool("remember", "Save one short fact worth "
              "remembering in future sessions.", fact="The fact")]

def execute(name, a):
    with open("memory.md", "a") as f:
        f.write(f"- {date.today()}: {a['fact']}\n")
    return "saved"

system = "What you remember:\n" + open("memory.md").read()

Skills: know-how loaded on demand

A skill is a folder with a SKILL.md: a name, a one-line description, then instructions. Only the descriptions go into the context at the start; when a task matches, the agent calls load_skill and the full instructions come in. A hundred skills cost a hundred lines. The format is the open Agent Skills standard. 06_skills.py

---
name: haiku
description: Write a haiku about any topic. Use when the
  user asks for a haiku or a very short poem.
---

# Haiku
Write exactly three lines with 5, 7 and 5 syllables.
Count the syllables of every word before answering.

Sub-agents: another list, the same loop

A sub-agent is a fresh context list with its own instructions and tools, run through the same loop. The main agent hands it a task; it might read twenty files, but only its short report comes back. The main context stays clean, and several can run in parallel. 07_subagent.py

def delegate(name, a):
    sub_context = [
        {"role": "system", "content": "You are a research sub-agent. "
            "Report your findings in at most 80 words."},
        {"role": "user", "content": a["task"]}]
    return loop(sub_context, READ_TOOLS, read_only)

Autonomy: a heartbeat

So far the agent only acts when you type. A heartbeat wakes it on a timer. OpenClaw does this every 30 minutes: the agent reads a plain checklist file, does what is needed and goes back to sleep. You steer it by editing the file. 08_heartbeat.py

# HEARTBEAT.md
- If there is a file called inbox.txt, summarise it in one sentence.
- If nothing needs attention, answer exactly: NOTHING TO DO

# heartbeat-log.md  (real output from the practice code)
## 2026-10-15 12:19
The meeting has been rescheduled to Friday at 10:00,
so remember to bring the budget draft.

Safety: capability is a trade-off

An agent that can send your email can send the wrong email. Models are not deterministic, and text from outside (a web page, a document, an email) can contain instructions that try to take over the agent: prompt injection. Treat everything an agent reads as data, never as orders.

Simon Willison's “lethal trifecta” is a useful test: private data, untrusted content and a way to send data out should never meet in one agent.

Least access

Only the tools and files the job needs.

Ask before acting

A human approves anything that cannot be undone.

Secrets out of reach

Keys and passwords outside the agent's view.

Log everything

Every tool call can be traced afterwards.

Challenges

From the agents-from-scratch workshop in BirgerMoell/agents, where the rule is to write the agent without AI coding tools:

Surprise yourself

Give the agent a tool and find a task where it uses it in a way you did not plan.

Write a skill

Teach it something your team does every week, in one SKILL.md.

Better compaction

Drop tool results first, keep decisions. Measure what the agent still remembers.

Real autonomy

Let the heartbeat do one useful thing a day, and log every action.

05Words you will meet

TokenThe unit a model reads and writes: a word or part of a word. Roughly four characters of English.
Context windowThe maximum number of tokens a model can take in one call, for example 200 000.
System promptThe first message: instructions that frame every answer.
Tool call / function callingA structured reply in which the model asks the program to run a named function with arguments.
HarnessEverything around the model: the loop, the tools, the context handling. The part you build.
CompactionReplacing older context with a summary when the window fills up.
RAGRetrieval-augmented generation: search a knowledge base and put the relevant pieces in the context.
MCPModel Context Protocol: a standard way to plug external tools into agents.
Prompt injectionInstructions hidden in content the agent reads, aimed at taking over its behaviour.
